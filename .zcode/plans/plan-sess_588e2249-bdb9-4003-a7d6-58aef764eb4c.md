## План: Фикс поиска коммитов (SHA и по сообщению)

### Симптом
Вводишь существующий SHA или название коммита из выбранной `upstreamBranch` — получаешь «не найдено».

### Корень проблемы (статический анализ `resolveCommits`)
В моей реализации `src/git.ts` три проблемы:

1. **Поиск по сообщению не работает из-за `from: upstreamBranch` без `to`**. simple-git формирует `git log upstreamBranch...` или подобное, что даёт пустой/неожиданный результат. Для `--grep`-поиска нужно звать `git log --grep=<query>` **без** `from` (по всей истории), а уже найденный коммит проверять на принадлежность к `upstreamBranch`.

2. **`--grep` чувствителен к регистру.** Пользователь мог ввести «рефакторинг» (с маленькой), а в коммите «Рефакторинг». Нужно `-i: true`.

3. **Частичные SHA нестабильны в `git.revparse([short])`.** На некоторых git/версиях rev-parse с 4–7-символьным префиксом падает, даже если коммит существует. Нужен fallback: если rev-parse упал, попробовать `git log --grep` (вдруг это сообщение) ИЛИ `git rev-parse --disambiguate=<prefix>`.

4. **Нет проверки вхождения в `upstreamBranch`.** Если пользователь ввёл полный SHA коммита, которого нет в выбранной ветке — вернётся валидный коммит, но «не из той оперы». Стоит проверять через `git merge-base --is-ancestor <sha> <upstreamBranch>` (коммит является предком ветки = входит в её историю).

### Стратегия фикса
Переписать `resolveCommits` с более надёжной стратегией разрешения каждого query:

```
для каждого query:
  1. Попытка A — SHA/ref через `git revparse([query])`.
     Если успех → candidateSha. Проверить вхождение в upstreamBranch (шаг 4).
  2. Попытка B — поиск по подстроке сообщения:
       `git.log({ "--grep": query, "-i": true, maxCount: 1 })`  ← БЕЗ from!
     Если успех → candidateSha. (вхождение уже косвенно обеспечено тем, что
     мы потом фильтруем — см. шаг 4.)
  3. Если оба провалились → notFound.
  4. Проверка вхождения candidateSha в upstreamBranch:
       `git mergeBase(["--is-ancestor", candidateSha, upstreamBranch])`
       exit code 0 → да, входит; не-0 → не входит (не found для этой ветки).
  5. Метаданные: `git.log({ hash: candidateSha, maxCount: 1 })`.
```

Важная семантика: если query разрезолвился, но коммит **не входит** в `upstreamBranch` — кладём в `notFound` (это и есть «коммит не в этой ветке», пользователь увидит его в alert'е).

### Детали реализации

**`src/git.ts` — переписать `resolveCommits`:**

```ts
export async function resolveCommits(cwd, upstreamBranch, queries) {
  const git = simpleGit({ baseDir: cwd });
  // checkIsRepo guard — без изменений

  const resolved: ResolvedCommit[] = [];
  const notFound: string[] = [];

  for (const raw of queries) {
    const query = raw.trim();
    if (query === "") continue;

    let candidateSha: string | null = null;

    // Попытка A: rev-parse (SHA/ref/короткий SHA)
    try {
      const r = await git.revparse([query]);
      const trimmed = r.trim();
      if (/^[0-9a-f]{4,40}$/i.test(trimmed)) {
        candidateSha = trimmed;
      }
    } catch { /* не SHA — пробуем grep */ }

    // Попытка B: поиск по подстроке сообщения (case-insensitive, без from)
    if (!candidateSha) {
      try {
        const l = await git.log({
          "--grep": query,
          "-i": true,
          maxCount: 1,
        });
        if (l.latest) candidateSha = l.latest.hash;
      } catch { /* ignore */ }
    }

    if (!candidateSha) {
      notFound.push(query);
      continue;
    }

    // Проверка вхождения candidateSha в upstreamBranch
    try {
      const isAncestor = await git.mergeBase([
        "--is-ancestor",
        candidateSha,
        upstreamBranch,
      ]);
      // mergeBase с --is-ancestor: exit 0 = да, иначе бросает/не-0
      // simple-git кидает исключение при не-0 exit → ловим ниже
    } catch {
      // коммит не в upstreamBranch
      notFound.push(query);
      continue;
    }

    // Метаданные
    try {
      const log = await git.log({ hash: candidateSha, maxCount: 1 });
      const latest = log.latest;
      if (!latest) { notFound.push(query); continue; }
      resolved.push({
        sha: latest.hash,
        shortSha: latest.hash.slice(0, 7),
        message: latest.message.split("\n")[0],
        author: latest.author_name,
        date: latest.date,
      });
    } catch {
      notFound.push(query);
    }
  }

  return { ok: true, resolved, notFound };
}
```

Заметка про `--is-ancestor`: simple-git кидает exception при exit code ≠ 0. `git merge-base --is-ancestor A B` выходит с 0 если A — предок B, и 1 если нет. Так что `try/catch` ловит «не предок» → коммит не входит в ветку → notFound. (Если `upstreamBranch` не существует — тоже exception → notFound, что разумно.)

### Замечание про edge-case
Если `upstreamBranch` пустой (пользователь не выбрал ветку) — `merge-base` упадёт, все коммиты попадут в `notFound`. Это уже защищается в webview-`onSubmit` (там есть `if (data.upstreamBranch.trim() === "") setError(...)`). Так что ОК.
