## План: Мгновенный поиск веток (кэш + клиентский фильтр)

### Причина текущей медленности
Каждое нажатие клавиши → debounce 300мс → round-trip webview→host→webview через `postMessage` → `git branch --list`. Суммарно: задержка ~300мс + IPC + запуск git-команды. Поэтому "mas → master" появляется с запаздыванием.

### Решение
**Загрузить все ветки один раз при открытии SelectBranch, закэшировать в webview, фильтровать клиентски.** Фильтрация в памяти — единицы миллисекунд, "mas" → "master" покажется мгновенно. На типичном репо (десятки/сотни веток) первичная загрузка тоже мгновенная.

### Тип данных
`BranchSearchResult` остаётся (поле `query` делаем опциональным/пустым для пакетной загрузки). В webview храним `BranchOption[]`.

### Поток данных (новый)
```
[open SelectBranch]
  useBranchSearch mount → postMessage({ command:"getAllBranches" })
                                      │
  [host] handleGetAllBranches → listAllBranches(cwd)
     git.branch(["--sort=-committerdate"])  ← ОДИН вызов, без --list
                                      │
  postMessage({ command:"allBranchesLoaded", data: { branches } })
                                      │
  [webview] кэш allBranches = branches

[пользователь печатает "mas"]
  onInputChange → setQuery("mas")
  Autocomplete.filterOptions(allBranches, { inputValue:"mas" })
     ↓ мгновенно, в памяти
  показывает [master, master-2.x, ...]
```

### Шаг 1. Host: `listAllBranches` вместо `listBranchesByGlob`
**Файл:** `src/git.ts`
- Удалить `listBranchesByGlob(cwd, query)`.
- Добавить `listAllBranches(cwd)`:
  - `git.branch(["--sort=-committerdate"])` — без `--list`, возвращает все ветки.
  - Возвращает `BranchSearchResult` с `query: ""` и `branches: BranchOption[]` (name+sha из summary).

### Шаг 2. Host: безопасная обёртка
**Файл:** `src/host/branches.ts`
- Заменить `safeSearchBranches(query)` на `safeListAllBranches()`.
- При `!cwd` → `{ ok:false, query:"", reason:"no-folder", ... }`.

### Шаг 3. Host: типы сообщений
**Файл:** `src/host/messages.ts`
- В `InboundMessage`: заменить `{ command:"searchBranches"; data:{ query } }` → `{ command:"getAllBranches" }`.
- В `OutboundMessage`: заменить `{ command:"branchesSearched"; data: BranchSearchResult }` → `{ command:"allBranchesLoaded"; data: BranchSearchResult }`.

### Шаг 4. Host: handler
**Файлы:** `src/host/commands/`
- Удалить `handleSearchBranches.ts`.
- Создать `handleGetAllBranches.ts` — вызывает `safeListAllBranches()`, шлёт `allBranchesLoaded`.

### Шаг 5. Host: роутер
**Файл:** `src/host/messageRouter.ts`
- Заменить импорт и `case "searchBranches"` → `case "getAllBranches": await handleGetAllBranches(deps)`.

### Шаг 6. Webview: типы
**Файл:** `webview-ui/src/types.ts`
- В `OutboundMessage`: `searchBranches` → `getAllBranches`.
- В `InboundMessage`: `branchesSearched` → `allBranchesLoaded`.

### Шаг 7. Webview: хук (главное изменение)
**Файл:** `webview-ui/src/features/select-branch/useBranchSearch.ts`
- При mount: `postMessage({ command:"getAllBranches" })`, подписка на `allBranchesLoaded` → `setAllBranches(data.branches)`.
- Состояние: `allBranches: BranchOption[]` (кэш), `loading: boolean` (первичная загрузка), `query: string`.
- Убрать debounce-эффект и отправку `searchBranches` — фильтрацией занимается Autocomplete (фильтр в памяти).
- API: `{ allBranches, loading, query, setQuery }`.

### Шаг 8. Webview: SelectBranch
**Файл:** `webview-ui/src/features/select-branch/index.tsx`
- `options={allBranches}` — весь кэш.
- `loading={loading}` — только первичная загрузка (спиннер).
- `inputValue={query}` + `onInputChange={(_,v)=>setQuery(v)}` — controlled input.
- **Убрать** `filterOptions={(x)=>x}` — вернуть дефолтный фильтр MUI Autocomplete (он мгновенно фильтрует по `inputValue`).
- `noOptionsText`: зависит от `query` (пустой → "Начните вводить", иначе "Ветки не найдены").

### Шаг 9. Сборка
- `npm run compile` (host).
- `npm run build-webview`.
