## План: Чекбокс «Использовать ветку-источник как основную»

### Решение по уточнению
При активном чекбоксе — **не создавать новую ветку**, а сделать `git checkout parentBranch` и перейти на Шаг 2. При снятии чекбокса — вернуть поля в дефолтное состояние.

### Поведение
- Чекбокс по умолчанию **off**.
- **On**: поле «Название релиза» `disabled`, визуально в нём показывается имя выбранной ветки-источника (или пусто, если ветка ещё не выбрана). По «Далее» → `useSourceBranch { fromBranch }` → хост `git checkout fromBranch` → переход на Шаг 2 с `releaseCtx = { fromBranch, releaseName: fromBranch }`.
- **Off** (включая возврат из on): `releaseName` сбрасывается в `""`, поле снова активно. По «Далее» — прежняя логика создания `releasePrefix + releaseName`.

### Типы сообщений
- `OutboundMessage` (webview→host) += `| { command: "useSourceBranch"; data: { fromBranch: string } }`.
- Ответ переиспользуем: те же `releaseBranchCreated` / `releaseBranchError`. Отдельные события не нужны — смысл ответа тот же (успех/провал переключения).

### Шаг 1. Host: git-операция checkout
**Файл:** `src/git.ts`
- Добавить `checkoutExistingBranch(cwd, branchName)`:
  - `checkIsRepo` guard.
  - `git.checkout(branchName)`.
  - Возвращает `CreateBranchResult` (переиспользуем существующий тип — для хоста/вебвуя это тот же контракт успеха/ошибки).

### Шаг 2. Host: безопасная обёртка
**Файл:** `src/host/branches.ts`
- Добавить `safeUseSourceBranch(fromBranch)`:
  - `cwd = getWorkspaceCwd()`; если null → `{ ok:false, reason:"git-error", message:"..." }`.
  - Делегирует в `checkoutExistingBranch(cwd, fromBranch)`.

### Шаг 3. Host: типы сообщений
**Файл:** `src/host/messages.ts`
- `InboundMessage` += `| { command: "useSourceBranch"; data: { fromBranch: string } }`.
- `OutboundMessage` — без изменений (уже есть `releaseBranchCreated`/`releaseBranchError`).

### Шаг 4. Host: handler
**Новый файл:** `src/host/commands/handleUseSourceBranch.ts`
- Зеркало `handleCreateReleaseBranch`, но вызывает `safeUseSourceBranch(message.data.fromBranch)` и шлёт те же `releaseBranchCreated`/`releaseBranchError`.

### Шаг 5. Host: роутер
**Файл:** `src/host/messageRouter.ts`
- Импорт + `case "useSourceBranch": await handleUseSourceBranch(message, deps); return;`.

### Шаг 6. Webview: типы
**Файл:** `webview-ui/src/types.ts`
- `OutboundMessage` += `| { command: "useSourceBranch"; data: { fromBranch: string } }`.

### Шаг 7. Webview: UI и логика в step-1
**Файл:** `webview-ui/src/screens/CreateRelease/step-1-create-branch.tsx`
- Новый state `useSource: boolean` (default `false`).
- `FormControlLabel` с `Checkbox` под полем «Название релиза».
- При `useSource === true`:
  - `releaseName` в UI показывается как `parentBranch` (через `value={useSource ? parentBranch : releaseName}`), поле `disabled`.
  - По «Далее» → `postMessage({ command:"useSourceBranch", data:{ fromBranch: parentBranch } })`.
  - При успехе → `onCreated({ fromBranch: parentBranch, releaseName: parentBranch })`.
- При `useSource === false` (включая переключение back):
  - `releaseName` сбрасывается в `""` (через `onChange` чекбокса: если снят — `setReleaseName("")`).
  - Поле активно, работает прежняя логика создания ветки.
- `canSubmit`: при `useSource` достаточно, чтобы `parentBranch` был непустой; иначе как раньше (`parentBranch` + `releaseName`).
- Слушатель `onMessage` уже есть и ловит `releaseBranchCreated`/`releaseBranchError` — работает для обоих команд без изменений.
