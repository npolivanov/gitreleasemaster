# План: фикс сохранения настроек (releasePrefix не применяется)

## Найденная корневая причина
В `src/host/settings.ts` функция `applySettings` записывает настройки по **неправильному ключу**:

```js
const config = vscode.workspace.getConfiguration("gitreleasemaster");  // уже секция
config.update("gitreleasemaster.releasePrefix", value, Global);        // ← двойной префикс
```

Когда `getConfiguration()` вызывается с именем секции (`"gitreleasemaster"`), `config.update` ожидает ключ **без префикса секции** — просто `"releasePrefix"`. Текущий код `"gitreleasemaster.releasePrefix"` создаёт буквально вложенный путь `gitreleasemaster → gitreleasemaster → releasePrefix`, который:
- не записывается в `settings.json` по правильному пути (подтверждено: в `~/Library/Application Support/Code/User/settings.json` записи `gitreleasemaster` нет вообще),
- не читается обратно через `config.get("releasePrefix")` → `readSettings()` всегда возвращает дефолт `"release/"`.

Это объясняет все симптомы: префикс остаётся дефолтным, список веток не меняется, перевод веток после смены prefix ничего не даёт (потому что `readSettings()` всё равно отдаёт дефолт).

## Фикс (одно изменение)
В `src/host/settings.ts`, функция `applySettings`: убрать префикс секции из ключа в `config.update`.

**Было:**
```js
config.update(`${CONFIG_SECTION}.${key}`, value, vscode.ConfigurationTarget.Global)
```
**Стало:**
```js
config.update(key, value, vscode.ConfigurationTarget.Global)
```

С комментарием на русском, объясняющим, почему ключ без префикса.

## Почему не нужно трогать handleUpdateSettings / перевод веток
Логика автоперевызова веток после смены prefix (`handleUpdateSettings.ts`) написана корректно — она заработает сама, как только `readSettings()` начнёт возвращать реальное значение. До фикса перевызов шёл, но `safeListBranches → readSettings` всё равно отдавал `"release/"`.

## Проверка
1. `npm run compile` — типы.
2. Ручная: открыть панель, сменить prefix на `fix/` → проверить, что в `settings.json` появляется `"gitreleasemaster.releasePrefix": "fix/"` и список веток обновляется.
3. `cd webview-ui && npm run build` — после чистки логов.
